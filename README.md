# 矿山管理系统简版

独立简版位于 `lite/` 目录，与原系统分开建设。功能范围及每次修改记录见[功能树](功能树.md)。

## 首页与入口

- [扫码密码入口](lite/access.html)：验证访问密码后进入首页。
- [简版首页](lite/index.html)：六个工作端口，员工申请端口由首页选择并在登记页锁定。
- [管理员后台](lite/management.html)：通过独立管理员密码进入，处理人员审核、车数统计、人员档案、车辆档案及离职清算核对。
- [Boss 端](lite/boss.html)：使用独立 Boss 密码进入。

首页保留司机端、挖机端、辅助司机端、调度端、Boss 端和中层管理端。原“管理端”员工卡片及登记入口已取消；旧管理端员工工作页链接转回首页，管理员继续使用首页页脚的密码入口。既有人员档案和照片保留，不自动转换为管理员。

## 主要流程

辅助司机端先选择具体岗位：铲车司机、加油车司机、水车司机、平地机司机、排土管理员，再进入锁定岗位的登记表并接受审核。原通用辅助司机申请保留，可在岗位选择页查看原登记；新申请必须选择具体岗位。

中层管理端先选择具体岗位：财务、测绘、后勤库管、统计、其他后勤人员，再进入锁定岗位的登记表并接受审核。调度保留首页独立入口，不属于中层管理子岗位。原通用中层申请保留查看和审核状态，新申请选择具体岗位；人员导出的申请端口归属中层管理端，岗位为具体名称。

五个员工端口从首页选择岗位，填写入职登记并等待管理员审核。管理员查看完整资料和附件、勾选确认核对后才可通过；资料修改后需重新核对。审核窗口支持通过、驳回、打印资料、选择照片打印和关闭。人员资料打印为单栏表格，含国籍、民族，不附照片清单；PDF 附件可打开查看。

人员档案支持停用、恢复、离职登记及返聘审核，保留历史记录；停用/离职人员停止工作端口访问和新增领用。人员及车辆均可导出带总表头的 Excel，包含完整文字信息，不含照片或附件元数据。

车辆档案按双列表单登记名称、类别、车架号、发动机号、燃油、入场日期及其他信息，支持合格证和进场照片。状态保留作业中、待命、维修中、停用。全部图片上传位置统一即时预览，并支持已保存图片回显。

## 运输三端

- 司机、挖机、调度审核通过后直接进入各自运输工作台。调度先建立白夜班排班、关联设备和装载挖机，再设置通用GPS装载区/卸载区，启用后人员接班检查。区域不再关联挖机，车次按司机排班绑定或临时选择的挖机归属。区域表单使用WGS84 / UTM平面坐标（X东向、Y北向，米），含分区和南北半球，旧区域自动转换显示；UTM保存时转换回GPS内部位置用于区域判断。中心定位精度由“用当前位置作为中心”自动获取并保存，手动改平面坐标或分区会清除旧精度。区域界面不再提供高程选项或采集高程；已保存的旧高程和车次快照保留。
- 使用前异常可拍照上报，责任直接关联同设备上一个实际使用班次驾驶员，不需要调度复核；首次使用无前任如实显示未记录，延续旧故障不重复定责。异常处理完成后记录恢复，主档案停用/维修设备不能直接放行。
- GPS有效停留装载区、离开装载区，再有效进入卸载区生成一趟完成记录；车辆与实际装载挖机共用同一条车次计算数量，卸载区决定物料。临时选择其他挖机仅下一趟有效，维修/保养暂停后不能开始新装载。
- 物料统一为“渣、煤、只记车数”三个下拉选项，区域、非卸载区卸料和分类修正保持一致。“只记车数”指采坑内垫路、修路等未离开采坑的运输，完成卸料后仍计1车；不要求驶出采坑。历史车次保留原值，新车次不猜测旧的自由文字分类。
- 非卸载区卸料在已有装载车次上由司机提交后立即计车，不经过调度确认。刷新、重复提交不增加同一车次，作废/冲销会同步反映到两端。
- 原生网页定位需本人授权并保持页面可见；隐藏页面或长时间断点将使在途记录待核对。位置模拟有独立标识与数量，不计入真实定位车数。区域示意为坐标与半径绘制，不使用外部道路地图。
- 运输记录独立存储于 `mine-management-lite-transport-v1`，照片沿用IndexedDB每张10MB，三端消息仅在当前浏览器内联动；没有跨手机数据同步或后台持续GPS。
- 新表单默认选填，可先保存草稿；启用排班/区域和执行作业时检查是否具备有效配置。本轮保留后勤物资入口，后勤新增功能和物资领用联调仍按开发顺序暂缓。

## 后勤物资

- 审核通过的员工从本人工作页进入“后勤物资申请”；后勤库管进入库存与发放工作台，财务进入赔偿复核。停用/休假人员可由登记状态页处理本人归还和清算，离职后仅查看历史。
- 申请预留库存，库管按实际发放调整并交付，员工确认后出库。库存不足阻止申请并发送缺货站内提醒；撤销已交付单需员工确认未领取/已全部退回后才释放预留。
- 入库单价必填；不可回收物资赔偿单价固定为0，可回收物资按最近一次有价入库自动生成只读单价。无入库价格的可回收物资暂不发放，旧缺价入库可在流水补录价格且不增加库存。未确认领用同步当前价格，确认时复核；已领用记录保留原快照。
- 可回收物资按员工持有管理，部分归还须库管验收；可用回库，损坏转待处理库存。不可回收物资不产生归还义务。
- 管理员原“物资领用”已迁到后勤库管端。旧记录保留，库管核实并补为历史持有或注明无需归还，不重复扣库存。
- 管理员办理离职先发起物资清算，列出未归还物资、待确认单据、旧记录及赔偿待办；员工不归还需本人确认，库管核实、财务复核通过后列入唯一待扣款清单，支持 Excel 导出。当前没有工资表，不会直接扣工资。
- 后勤数据使用独立键 `mine-management-lite-logistics-v1`；库存变更通过浏览器事务锁串行处理。消息为同浏览器站内消息，不是手机后台推送。
- 登记页可凭当前岗位的登记编号与手机号继续原申请；同一浏览器不同页签保留各自岗位会话，便于完成申请、库管发放、本人确认及财务复核。此流程不替代正式账号认证。

## 数据保存方式

记录保存在当前浏览器 localStorage，附件保存在 IndexedDB，单文件上限 10 MB。数据不跨手机、浏览器或管理员设备同步；扫码与审批需使用同一浏览器的数据。管理员和 Boss 密码分别保存在当前浏览器；GitHub Pages 前端入口校验不等同于服务器身份认证。当前未接入共享数据库与正式账号系统，请勿填写真实敏感信息。

## 坐标转换依赖

UTM转换使用随项目保存的 [Proj4js 2.22.0](lite/vendor/README.md)，许可与来源一并保留；运行时不依赖外部坐标转换CDN。投影参考 [PROJ UTM 文档](https://proj.org/en/stable/operations/projections/utm.html)，浏览器高度含义参考 [W3C Geolocation](https://www.w3.org/TR/geolocation/#altitude)。
